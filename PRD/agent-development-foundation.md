# PRD: основа агентской разработки и Roadmap оживления

## Цель и границы

Создать применимый процесс и проверяемую очередь оживления `vetmanager-token` без изменения исполняемого API, зависимостей, CI, секретов и публичного текста. База token `main`: `ad2bac2fccfa75a1ae38c77ba110626aed721d61`; образец rest-api `main`: `44c137cb17b9c05789b20c0bdfd0bce0c41591b8`. Оба удалённых HEAD проверены 2026-10-24; рабочая копия token перед изменениями была чистой. В rest-api локальный `main` отставал, поэтому образец прочитан из `origin/main` без изменения его checkout.

## Проверенные факты

- В token нет `AGENTS.md`, `Roadmap.md`, `Tasks.md`, `PRD/` на исходном commit. `README.md`, `composer.json`, `Makefile`, `docker/Dockerfile`, `.github/workflows/CI.yml`, `src/` и `tests/` просмотрены.
- В `src/functions.php` объявлены `credentials()`, `token()`, `token_with_client()`. Первый `token()` строит ленивый URL и `Token\FromGateway`; второй путь принимает `ClientInterface` и строит `Token\FromResponse`. `FromGateway` сохраняет трёхаргументный конструктор; обе реализации вызывают запрос при `asString()` и кешируют непустой успешный токен. `Url\Lazy` сохраняет лишь успешно разрешённый URL; после ошибки возможна следующая попытка. Это подтверждают `tests/unit/FunctionsTest.php`, `TokenGatewayCompatibilityTest.php`, `TokenBillingRetryTest.php`, `Url/LazyTest.php`.
- Composer: `otis22/vetmanager-url:~0.1 || ^1.1`, `guzzlehttp/guzzle:^7.1`, нет строки `php`; `composer.lock` отслеживается. README одновременно говорит о PHP 8.0/8.1 и использовании URL 1.1 с PHP 7.4+. Makefile по умолчанию 8.0. CI: PHP 7.3/7.4/8.0 и URL 0.3.2/1.1.0 на 7.4/8.0, интеграция с CI secrets на каждом push/PR. Эти источники не дают единой согласованной политики PHP.
- В rest-api `origin/main:composer.json` указан `otis22/vetmanager-token:^0.2.0`; его процесс задаёт единый Roadmap, Tasks с зависимостями, PRD до нетривиальных изменений, независимое ревью PRD/diff и запись точных проверок. Специфичные для rest-api 90% покрытия и PHP 7.3–8.5 нельзя автоматически переносить как обещание token.
- На otis-home доступны Docker и daemon; `php` и `composer` на хосте отсутствуют. Воспроизводимость `make all` не установлена этим документальным этапом.

## Решение

Ввести короткий `AGENTS.md`, очередь `Roadmap.md`, измеримую приёмку `Tasks.md`, шаблон PRD и правила доказуемого ревью. Разделить P0: окружение, изоляция интеграции/CI, контрактные тесты; затем P1: матрица PHP/URL/Guzzle и совместимый выпуск. Статусы будущих этапов оставить `todo`. README и runtime пока не менять.

## Критерии приёмки текущего этапа

1. Все документы ссылаются на реальные файлы и друг на друга; очередность и статусы не выдают будущие работы за выполненные.
2. Факты о публичном контракте, CI и зависимостях соответствуют исходному SHA, а PHP-матрица обозначена открытым вопросом.
3. `git diff --cached --check`, проверка внутренних ссылок и полный просмотр diff выполнены; точные команды, exit codes и ограничения записаны ниже.
4. Независимый рецензент проверил полный diff, замечания разобраны. Документальный commit допустим локально; CI и публикация ветки остаются гейтом I1 после изоляции интеграции. Если заключения нет, F3/F4 остаются открытыми.

## Открытые вопросы владельцу

1. Какую версию PHP считать нижней и какие версии реально поддерживать? Текущие README, CI и Composer противоречат друг другу; решение требуется перед правкой ограничений и публичного текста.
2. Какая изолированная тестовая клиника и способ передачи тестовых credentials допустимы для интеграции? Значения не нужны в PRD или чате.
3. Какие релизные обещания для линии 0.2.x существенны помимо уже используемого `rest-api:^0.2.0`? По умолчанию все перечисленные контракты сохраняются.
